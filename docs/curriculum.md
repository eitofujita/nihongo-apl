# 教材（JLPT N5〜N3）と校閲の状態

## 収録範囲

| レベル | 文法 | 単語 | 単語レッスン |
| --- | --- | --- | --- |
| N5 | 73項目（初期20項目＋追加53項目） | 720語（初期100語＋620語） | 72 |
| N4 | 84項目 | 668語 | 67 |
| N3 | 104項目 | 2,139語 | 214 |
| 合計 | 261項目 | 3,527語 | 614レッスン・4,250問 |

- 文法レッスンの構成は、説明（英・露）、例文、3問の練習（四択または入力）です。
- 単語レッスンは10語ずつで、語ごとに1問、計10問です。不正解の選択肢は同じレベル・同じ品詞の語から選び、意味が重なる語は外しています。
- 同じレベルの中では、文法と単語が交互に並ぶ学習順にしています。
- 初期30レッスンの教材IDと問題IDは変えていないため、以前の進捗はそのまま有効です。

JLPTは2010年以降、公式の語彙・文法リストを公表していません。このため「100%」は公式リストに対する網羅ではありません。単語は下記の公開リストを全件収録しています。文法は一般的なN5〜N3の文型一覧をもとに、独自に項目を選定しています。

## データの置き場所と生成

教材の正本は`content/`にあり、`npm run content`で次のものを生成します。

| 入力 | 内容 |
| --- | --- |
| `content/legacy.json` | 初期30レッスン（ID維持のため固定） |
| `content/grammar/n5.txt`, `n4-*.txt`, `n3-*.txt` | 文法。書式は`scripts/build-content.mts`の冒頭を参照 |
| `content/vocab/n5.csv`, `n4.csv`, `n3.csv` | 単語・読み・英語の意味（公開リスト） |
| `content/vocab/ru-*.txt` | ロシア語訳と、必要な場合の英訳の修正 |

| 出力 | 用途 |
| --- | --- |
| `src/content/generated/catalog.json` | 全ページで読む軽量な索引（タイトル・問題ID） |
| `src/content/generated/n5.json`ほか | レベル別の本文。ブラウザが必要なときだけ読む |
| `supabase/migrations/202611180001_curriculum_n5_n3.sql` | 追加分の正解データ（DB採点用） |
| `supabase/setup.sql`の生成ブロック | 新規プロジェクト用 |

生成時に、ID重複、四択の数と重複、正解の有無、空の説明、`?`の残った選択肢、ロシア語訳の欠落・余剰を検査します。問題があると生成は失敗します。テストでは、生成物とDBの正解データが一致することも確認しています。

教材本文はCloudflare Workerに含めません。Workerに入るのは索引だけで、本文は静的ファイルとして配信します。無料枠のWorkerサイズ上限（圧縮後3MiB）に余裕を残すためです。

## 品質の境界

- 文法の例文・問題・解説、ロシア語訳はAIの支援で作成しました。人による校閲はまだ行っていません。
- 選択肢が文脈上ほかにも正解になりうるものは、作成時に確認して差し替えています。ただし、自然さや別解の有無は日本語教師による確認が必要です。
- 単語の英語の意味は公開リストをもとに短くしています。元データに明らかな誤りがあったものは修正しました（例：中学校）。
- 入力式の問題は正解を1つだけ受け付けます。表記ゆれ（漢字・かな）には対応していません。

## 校閲時の確認項目

1. 日本語の自然さ、読み、学習段階に合う語彙・漢字。
2. 四択のほかの選択肢が、同じ文脈で正解にならないか。
3. 入力問題の許容解、異表記、丁寧さの扱い。
4. 英語・ロシア語の意味・時制・否定・指示範囲が日本語と一致するか。
5. 解説が問題文と正解に対応しているか。
6. 単語の複数の読み・意味の扱い（例：日本＝にほん／にっぽん）。
7. 文法項目のレベル分け（N4とN3の境界など）。

## 学習開始チェックと推薦

診断は初期の基本文法10問を使う目安です。JLPTの合否やレベルは判定しません。ホームでは、期限が来た復習、誤りが残る項目、未完了レッスンの順に提案します。復習は1回20問ずつです。

## 漢字の書き取り（試作・N5のみ）

`/kanji`で、N5の漢字103字を指・ペン・マウスで書いて練習できます。手順は「なぞる → グリッドだけで書く → 意味と読みだけを見て書く」の3段階です。

- 判定はブラウザ内だけで行い、サーバーやWorkerのCPU時間は使いません。1画ごとに、位置・書き始めの向き・長さを確かめます。後の画を先に書いた場合は「書き順の誤り」として不正解にします。
- 進捗は今のところ端末内（localStorage）だけに保存します。アカウントへの同期はまだありません。
- 漢字リストは独自に選んだものです（JLPTの公式漢字リストはありません）。読みと意味は主なものに絞っています。

| 入力 | 出力 |
| --- | --- |
| `content/kanji/n5.txt`（漢字・音読み・訓読み・英語・ロシア語） | `src/content/generated/kanji.json`（索引） |
| KanjiVGのSVG（リポジトリには含めない） | `public/kanji/<コードポイント>.json`（書き順パス。1字ずつ読み込む） |

再生成するときは、[KanjiVGのリリース](https://github.com/KanjiVG/kanjivg/releases)から`kanjivg-*-main.zip`を取得・展開し、`npm run kanji -- <展開先>/kanji`を実行します。テスト（`tests/kanji.test.ts`）では、全字の全画が手本どおりに書けば正解になること、少しずらした線でも正解になること、次の画を先に書くと不正解になることを確認しています。
